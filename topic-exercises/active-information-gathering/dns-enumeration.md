# DNS Enumeration

## VM1

Now that you have proven your DNS prowess, let's see you put it to work on a real unknown network. The first step is to identify the lab's DNS server. The network on VM Group 1 is private and the domain name is currently unknown; however, you do know the lab's IP range, and that is plenty of information for this problem. Take an active approach to scan this IP range identify the host(s) listening on the DNS port, and then query those servers to find the true DNS server for the public domain. Then, identify the full domain name of the main DNS server. The flag is in a TXT record with the same name as the full domain name.

### Response

Investigating the network began with `nmap`.&#x20;

The addresses for the network were all in the range `192.168.229.0/24`

```
kali@kali$ nmap -sV --script=dns-service-discovery -p53 192.168.229.1-150

...

Nmap scan report for 192.168.229.149
Host is up (0.064s latency).

PORT   STATE SERVICE VERSION
53/tcp open  domain  Simple DNS Plus
Service Info: OS: Windows; CPE: cpe:/o:microsoft:windows

...

Nmap done: 150 IP addresses (11 hosts up) scanned in 9.65 seconds
```

* Only interesting results were kept

At this point I struggled for awhile trying to get `host`/`dig`/`nslookup` commands to work with the IP range but they would not.

Eventually I found [this](https://www.reddit.com/r/oscp/comments/wdpuem/issues\_with\_dns\_enumeration/) Reddit thread which suggested reading about the `/etc/resolv.conf` file. This is a list of DNS nameservers the system will attempt to use. I tried adding the IP of the known DNS server (`192.168.229.149`) to my `/etc/resolv.conf` file.

#### Original

{% code title="/etc/resolv.conf" %}
```
# Generated by NetworkManager
nameserver 192.168.122.1
```
{% endcode %}

#### Modified

{% code title="/etc/resolv.conf" %}
```
# Generated by NetworkManager
nameserver 192.168.229.1
nameserver 192.168.122.149
```
{% endcode %}

This still did not work.

```
$ host 192.168.229.149    
Host 149.229.168.192.in-addr.arpa. not found: 3(NXDOMAIN)
```

Eventually I realized the order of the items in the /etc/resolv.conf file mattered. I reordered them, placing the target network's first and retried.

{% code title="/etc/resolv.conf" %}
```
# Generated by NetworkManager
nameserver 192.168.229.149
nameserver 192.168.122.1
```
{% endcode %}

```
$ host 192.168.229.149      
149.229.168.192.in-addr.arpa domain name pointer dc.MAILMAN.com.
```

From there, I queried a TXT record for the domain name per the prompt.

```
$ host -t TXT dc.MAILMAN.com
dc.MAILMAN.com descriptive text "OS{c9e21a07ae94f069c74eeeac76add7ac}"
```
